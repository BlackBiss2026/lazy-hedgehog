# מעשה בקיפוד עצלן (שאלת רשות)

> מתוך חוברת C – שאלות לחזרה (עמ' 110).

## המשימה

יש לי חבר, דפק ת'ראש בהודו, חושב שהוא קיפוד. קוראים לו משה.

משה מאוד עצלן. הוא חי בעולם ובו 10,000 משבצות, המסודרות בריבוע של 100X100.
ידוע כי לכל משבצת בעולם שלו יש "משקל" הקובע כמה קל יהיה לעבור במשבצת הזו (למשל, אם משבצת מסויימת ממוקמת על הר, יהיה קשה מאוד לעבור אותה, כי היא גבוהה וצריך לטפס).
משה נמצא במשבצת השמאלית העליונה של העולם שלו, וברצונו להגיע אל הפינה הימנית התחתונה (שם מחכה לו זוגתו שתחייה, צביה).

עליכם לכתוב תוכנית שמקבלת את מטריצת העולם של משה (מתוך קובץ, אלא מה חשבתם, שתקלידו אותה?) ומדפיסה את המסלול הקל ביותר (סכום המשקלים של המשבצות שיעבור הוא הקטן ביותר) שעל משה לעבור כדי להגיע לפינה הימנית התחתונה.

מסתבכים עם האלגוריתם למציאת המסלול הקל ביותר? חפשו ב-google את Depth First Search. רץ ממש לאט? מה עם Dijkstra? עדיין מבאס? על genetic algorithms שמעתם? ועל אלגוריתם A* (A כוכבית, או A-star)?

> לשאלה הזו יש פוטנציאל היסחפות אינסופי. יש כמה אנשים שעשו דוקטורט על השאלה הזו. אם פתרתם אותה בדרך כלשהי, אז תנסו את הדרכים האחרות אם יש לכם זמן, ורק אם יש לכם זמן.

## הגדרות מדויקות (לצורך הבדיקה האוטומטית)

**הרצה**

```bash
./build/hedgehog <world-file>
```

**פורמט קובץ העולם**

```
3 3
1 9 1
1 9 1
1 1 1
```

- שורה ראשונה: מספר השורות ומספר העמודות (שלמים חיוביים). גודל העולם לא חייב להיות 100×100.
- אחריה `rows × cols` משקלים: מספרים שלמים בין `0` ל-`1000`, מופרדים ברווחים ובשורות חדשות.

**תנועה**

- משה זז צעד אחד בכל פעם: **למעלה, למטה, ימינה או שמאלה**. בלי אלכסונים.
  (בחוברת המקורית אפשר לבחור. כאן התנועה קבועה כדי שיהיה אפשר לבדוק.)
- מותר לזוז גם למעלה ושמאלה. לפעמים המסלול הקל ביותר מתפתל.
- משקל המסלול = סכום המשקלים של **כל** המשבצות במסלול, כולל משבצת ההתחלה ומשבצת הסיום.

**פורמט הפלט (stdout)**

```
5
0 0
1 0
2 0
2 1
2 2
```

- שורה ראשונה: משקל המסלול.
- אחריה המסלול, משבצת בכל שורה: `שורה עמודה` (מתחילים מ-0), מ-`0 0` ועד `rows-1 cols-1`.
- אם יש כמה מסלולים קלים ביותר – כל אחד מהם יתקבל.

**ביצועים**

כל בדיקה מוגבלת ל-10 שניות, ויש בדיקות של עולם 100×100. מעבר על כל המסלולים האפשריים (DFS נאיבי) לא יסיים בזמן.

**שגיאות** – הודעה ל-**stderr** וקוד יציאה `1`, בלי פלט ל-stdout:

- מספר ארגומנטים שגוי, או קובץ שלא ניתן לפתוח.
- עולם לא תקין: גודל לא חיובי, משקל שאינו מספר, משקל מחוץ לטווח 0–1000, חסרים משקלים, או נתונים מיותרים אחרי העולם.

הצלחה: קוד יציאה `0`. כל זיכרון שהוקצה משוחרר.

## איך עובדים

```bash
make                       # קימפול ל-build/hedgehog
make test                  # כל הבדיקות
make asan                  # הבדיקות עם AddressSanitizer
tests/run_tests.sh 04_needs_detour   # בדיקה אחת
./tests/grade.sh -v        # הציון שתקבלו, עם פירוט כישלונות
```

כל בדיקה היא תיקייה ב-`tests/cases` עם `world.txt` ו-`expected_cost` (המשקל של המסלול הקל ביותר). הסקריפט `tests/check_path.py` בודק שהמסלול שהדפסתם חוקי, שהסכום נכון ושהוא באמת הקל ביותר.
מותר לחלק את הקוד לכמה קבצי `.c` / `.h` בתוך `src/`.

## הגשה

- כל `git push` מריץ את הבדיקות אוטומטית. את הציון רואים בלשונית **Actions** של המאגר שלכם ← הריצה האחרונה ← **Summary**.
- ✅ ירוק = 100. ❌ אדום = חלק מהבדיקות נכשלו – הטבלה ב-Summary מראה אילו.
- הציון שנספר הוא של ה-push האחרון לפני הדדליין.
- **אסור לשנות** את התיקיות `tests/` ו-`.github/`. מאגר שבו הן שונו מסומן אצל הסגל.
